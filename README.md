# spring-gift-wishlist

## Step 1 : 유효성 검사 및 예외 처리
### 요구사항 분석
- 상품을 추가하거나 수정하는 경우, 클라이언트로부터 잘못된 값이 전달될 수 있다.
  잘못된 값이 전달되면 클라이언트가 어떤 부분이 왜 잘못되었는지 인지할 수 있도록 응답을 제공한다.
- 상품 이름은 공백을 포함하여 최대 15자까지 입력할 수 있다.
- 특수 문자 검증
- "카카오"가 포함된 문구 검증
### 구현 방향
- Service layer의 create와 update 로직에서 `try-catch`문을 중복하여 사용하지말고, `@ExceptionalHandler` 사용
- 상품 이름은 `@NotBlank`로 가장 엄격하게 입력값을 검증함과 동시에 `@Size`를 이용
- `@Pattern`과 `regex`를 이용
- `Custom Validator` 이용

## Step 2 : 회원 로그인
### 요구사항 분석
- 회원가입 API 구성
    - 이메일,비밀번호를 이용한 토큰 발급 기능 구현
    - (선택) 회원을 조회,추가,수정,삭제할 수 있는 관리자 화면 구성
- 로그인 API 구성
- ``401 Unauthroized`` 와 ``403 Forbidden``을 구분하여 예외처리
### 구현 방향
| 기능   | Method | URL                 |Request Body | Response Body | 상태코드      |
|------|--------|---------------------|--------------|---------------|-----------|
| 회원가입 | POST   | /api/users/register | 이메일, 비밀번호| 토큰 정보| 201:정상가입  |
| 로그인  | POST   | /api/users/login    | 이메일, 비밀번호 | 토큰 정보| 200:정상로그인 |
- ``jwt web token`` 사용
- 도메인에서 회원 인증 로직 구현(isEuqalPassword())
- 응용 서비스에서 토큰 생성 구현

# spring-gift-enhancement
## Step 1 : 엔티티 매핑
### 요구사항 분석
- DDL을 통해 엔티티 클래스와 리포지토리 클래스를 작성해본다.
- 역시 DDL을 통해 객체의 참조와 테이블의 외래 키를 매핑해서 객체에서는 참조를 사용하고 테이블에서는 외래 키를 사용할 수 있도록 한다.
- `@DataJpaTest`를 사용하여 학습 테스트를 수행한다.

### 구현 방향
- member, product, wish DDL의 ```id         bigint generated by default as identity,```
    - ID 매핑 구현: `@Id` + `@GeneratedValue(strategy = GenerationType.IDENTITY)`
        - 1차 캐시 Key 역할 및 auto_increment를 통해 쿼리 최적화
- DDL 외래키 제약조건
    - ```sql
    alter table if exists wish
    add constraint fk_wish_member_id_ref_member_id
    foreign key (member_id)
    references member

    alter table if exists wish
    add constraint fk_wish_product_id_ref_product_id
    foreign key (product_id)
    references product
    ```
    - 연관관계 매핑
        - Wish 엔티티에서 member_id, product_id 외래키를 가진다.
        - 여러 Wish가 하나씩의 member, product를 가리키게 되므로 `@ManyToOne`을 통해 다대일 관계 표현
- 객체 설계를 테이블 설계 기반이 아닌 참조를 사용하도록 수정
## Step 2 : 페이지네이션 적용
### 요구사항 분석
- 상품 조회에 페이지네이션 적용 (GET)
- 위시리스트에 페이지네이션 적용 (GET)
- 정렬 방법은 자유롭게 수행

### 구현 방향
- Spring JPA의 `Pageable`을 활용하여 각 계층 코드 수정 / 반환 타입 : `Page<T>`
- 사전 순서의 내림차순 정렬 기능 제공

## Step 3 : 상품 옵션
### 요구사항 분석
- 옵션 이름은 공백을 포함하여 최대 50자를 입력할 수 있다.
- ( ), [ ], +, -, &, /, _ 외 특수문자 사용 불가
- 옵션 수량은 최소 1개 이상 1억 개 미만이다.
- 중복된 옵션은 구매 시 고객에게 불편을 줄 수 있다. 동일한 상품 내의 옵션 이름은 중복될 수 없다.
- 상품 옵션의 수량을 지정된 숫자만큼 빼는 기능을 구현한다

### 구현 방향
- 옵션은 수량 증감, 이름 중복 여부 등의 책임을 지니므로 하나의 도메인
- 특히 상품과 옵션이 1:N 관계를 가질 것이므로 엔티티로 구현
- 옵션 이름에 관한 규칙은 Bean Validation의 어노테이션을 이용하여 구현

# spring-gift-order
## Step 1 : 카카오 로그인
### 요구사항 분석
- 카카오계정 로그인을 통해 인증 코드를 받는다.
- 토큰 받기를 통해 액세스 토큰을 추출한다.
- 앱 키, 인가 코드가 유출되지 않도록 한다.
- (선택) 인가 코드를 받는 방법이 불편한 경우 카카오 로그인 화면을 구현한다.

### 구현 방향
- 클라이언트가 없는 상황이므로 REST API를 직접 호출 하여 `http://localhost:8080/?code={AUTHORIZATION_CODE}` 에서 인가 코드를 추출한다.
- 동기식 HTTP 통신으로 Spring이 제공하는 RestClient HTTP Client 도구를 사용하여 액세스 토큰을 추출한다.
- 환경변수로 앱 키와 인가 코드를 설정하여 유출을 방지한다.

## Step 2 : 주문하기
### 요구사항 분석
- 카카오톡 메시지 API를 사용하여 주문할 때 수령인에게 보낼 메시지를 작성한다.
- 상품 옵션과 해당 수량을 선택하여 주문하면 해당 상품 옵션의 수량이 차감된다.
- 해당 상품이 위시리스트에 존재하는 경우 위시리스트에서 삭제한다.
- ``나에게 보내기``를 통하여 주문내역을 카카오톡 메시지로 전송한다.
  - 이 때, 메시지는 ``메시지 템플릿``의 기본 템플릿 또는 커스텀 템플릿을 자유롭게 사용한다. 

### 구현 방향
- 카카오 메시지 API를 사용해야하므로 Token entity를 구성하여 DB에 저장하도록 구현한다.
- Access Token은 평문/ Refresh Token은 암호화하여 저장하며 만료 시 자동 갱신 로직을 구현한다.
- '선물하기'의 목적에 맞게 주문 생성과 메시지 전송을 하나의 트랜잭션으로 구성한다.
- 이외 상품 옵션 차감과 위시 삭제 로직을 구현한다.
